# 🥜 goober, a less than 1KB css-in-js solution.

## Why the fork

Goober is awesome, but the styled function didn't work in waku ssg / ssr and needed some optimizations. Beyond that, I also wanted to adjust the API of styled and css to work better with my own workflows and patterns.

At the same time, it also seemed like an interesting task to refactor the project with more modern js patterns and to learn how goober works internally.

## Quickstart

Use the `css` function to inject styles and generate a css class:

```tsx
import { css } from "goober"

const red = css`
  color: red;
`

const Text = () => <span className={red}>Some Text</span>
```

## API

### css

Create static styles, inject them into the DOM, and generate a css class.

**Usage:**

```tsx
const boldFont = css`
  font-weight: 800;
`
const redText = css`
  color: red;
`
const important = css`
  ${boldFont}
  ${redText}
`

const Text = () => <span className={important.class}>Important Text!</span>
```

### glob

Insert global CSS rules, that shoudl not be scoped to a css class.

**Usage:**

```ts
glob`
  html, body {
    height: 100%;
  }
  * {
    box-sizing: border-box;
  }
`
```

### keyframes

Create reusable animation blocks. Returns the name of the animation, to be used inside other goober functions (i.e. `css`).

**Usage:**

```ts
const rotate = keyframes`
  from {
    rotate: 0deg;
  }
  to {
    rotate: 360deg;
  }
`

const className = css`
  animation: ${rotate} 1s ease-in-out;
`
```

### recipe

Create dynamic style recipes that can be adjusted via props.

**Usage:**

```ts
const text = recipe<{ bold: boolean }>(({ bold }) => [
  css`
    font-size: 1rem;
    font-weight: 400;
  `,
  bold &&
    css`
      font-weight: 700;
    `,
])
const boldText = text({ bold: true })
```

### styled

Create React components that have styles attached to them.

> Note: Make sure to call setup with an `jsx` function (i.e. `React.createElement`) first!

**Usage:**

With static styles:

```tsx
const Button = styled("button")`
  background: white;
  &:hover {
    background: gray;
  }
`

const btn = <Button>Button</Button>
```

Use the `as` prop to dynamically change the rendered element:

```tsx
const Button = styled("button")`
  background: white;
  &:hover {
    background: gray;
  }
`

const anchor = (
  <Button as="a" href="https://goober.js.org">
    Goober
  </Button>
)
```

With dynamic styles (like recipe):

```tsx
const Button = styled("button")<{ disabled: boolean }>(({ disabled }) => [
  css`
    background: white;
    &:hover {
      background: gray;
    }
  `,
  disabled &&
    css`
      pointer-events: none;
      opacity: 0.5;
    `,
])

const btn = <Button disabled>Disabled button</Button>
```

Filter props that should not be forwarded to the dom element:

```tsx
const Button = styled("button")<{ invert?: boolean }>(
  ({ invert }) => css`
    background: ${invert ? "black" : "white"};
    &:hover {
      background: gray;
    }
  `
).filterProps(["invert"])

const btn = <Button invert>Button</Button>
```

### setup

Customize the behvaior of goober. Needs to be called on app startup first, before calling any other goober functions.

You ensure this, by creating a new file, calling the setup function in there, and then re-export everything from goober. In your app, now only import from this new file.

**Parameters:**

- config `object`: The configuration to apply
  - config.prefixer `(key: string, value: string) => string`: Transform css output, e.g. to add `-webkit-` and `-moz-` prefixes

**Usage:**

```ts
// src/lib/goober.ts
import { setup } from "goober"

const prefixable = new Set(["backdrop-filter"])

const prefixer = (key: string, value: string) => {
  const default = `${key}:${value};`
  const lines = [default]

  if (prefixable.has(key)) {
    lines.unshift(`-moz-${default}`)
    lines.unshift(`-webkit-${default}`)
  }

  return lines.join("\n") + "\n"
}

setup({ prefixer })

export * from "goober"
```

### extractCss

Returns the CSS generated by calls of goober function (i.e. css), to use it for example in SSR / SSG environments. Call this at the end of rendering execution, styles that are generated after calling extractCss will be missing.

Insert them in a style tag with the id "\_goober", to allow client side goober calls to re-use the styles.

**Usage:**

```tsx
import { extractCss, GOOBER_ID } from "goober

const GooberStyles = () => (
  <style id={GOOBER_ID}>{extractCss()}</style>
)
```
